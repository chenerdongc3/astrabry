# 仓库结构说明

这次整理的目标不是大规模重构，而是先把“主应用”、“归档原型”和“外部抓取依赖”这三类内容分清楚。

## 当前建议认知

- `src/`
  React Web 主应用，当前真正对外展示和继续迭代的前端都在这里。
- `astramvp/backend/`
  FastAPI 后端，负责账号管理、数据采集入口、鉴权状态和刷新逻辑。
- `astramvp/agent/`
  Agent 编排与策略记忆逻辑。
- `prototypes/vue-command-center/`
  历史 Vue 原型，已归档，不参与当前主应用构建。
- `vendor/xhs/`
  小红书抓取相关的外部/辅助模块集合，用来与主业务代码边界分离。

## 为什么这样整理

- 让新读者能第一眼看出当前主 Web 入口在哪里。
- 避免 `astramvp/` 同时承载“正式后端”和“历史前端原型”，造成误判。
- 把抓取和存储辅助代码单独归类，减少它们和主业务 API 目录混在一起的认知负担。

## 兼容性说明

- 根目录仍保留 `xhsmedia`、`xhsstore`、`xhs_config.py` 的兼容入口。
- 现有依赖这些导入路径的脚本，不需要立刻跟着改路径。
- 新代码如果要直接接入小红书辅助模块，优先从 `vendor/xhs/` 视角理解其职责边界。
